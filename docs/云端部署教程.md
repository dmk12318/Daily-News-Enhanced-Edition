# 部署到云端（GitHub Actions 版）

目标：每天 **北京时间 08:00** 由 GitHub 的服务器自动抓取、写专栏、发布网页，**不需要你的电脑开机**。

仓库：`https://github.com/dmk12318/Daily-News-Enhanced-Edition`
成品网址：`https://dmk12318.github.io/Daily-News-Enhanced-Edition/`

> 和 `rizhilu` 的区别：rizhilu 是已经跑起来的初代产品，这个仓库是增强版实验田，
> 稳定一段时间后再合并回去。两者**各自独立运行**，互不影响。

| 需要 | 说明 |
| --- | --- |
| GitHub 账号 | `dmk12318` |
| 本机能推送 | 因为你机器上还没有任何 GitHub 凭据，**第一次要你登录一次**（见第二步） |
| 一个 LLM API Key | 见第三步。建议用 DeepSeek，和 rizhilu 一致 |

## 二、第一次推送（你需要做的唯一手工步骤）

仓库已经在本地建好、提交好了，只差推送。**在你自己的 PowerShell 窗口**里跑：

```powershell
cd D:\File\Codex\每日新闻
git push -u origin main
```

会弹窗让你登录 GitHub（Git Credential Manager），**登录一次就够了**——凭据会被存进
Windows 凭据管理器，以后所有推送（包括我代跑和云端）都不用再登录。

成功标志：出现 `Branch 'main' set up to track 'origin/main'`。

> 如果之前那个 `site/` 的仓库已经推过东西，先跑一次
> `git pull --rebase origin main` 再推，避免历史冲突。

---

## 三、申请 API Key 并配置

### 3.1 申请 Key

去 DeepSeek 开放平台（`platform.deepseek.com`）注册 → API Keys → 创建。

**当前可用的模型名只有两个**：

- `deepseek-flash` —— 快、便宜，适合每天跑的活，**推荐**
- `deepseek-v4-pro` —— 更强、更贵

> 旧的 `deepseek-chat` / `deepseek-reasoner` 已下线，别填这两个。

### 3.2 存进 GitHub（**不要贴在聊天里**）

打开仓库 → **Settings** → 左侧 **Secrets and variables** → **Actions**：

**Secrets 页**（加密，不可读回）→ New repository secret：

| Name | Value |
| --- | --- |
| `EDITORIAL_API_KEY` | 你的 API Key |

**Variables 页**（明文，方便改）→ New repository variable：

| Name | Value |
| --- | --- |
| `EDITORIAL_BASE_URL` | `https://api.deepseek.com` |
| `EDITORIAL_MODEL` | `deepseek-flash` |

> 把模型名放 Variables 而不是 Secrets：以后想换成 `deepseek-v4-pro` 只要改这一处，
> 不用重新填密钥。

---

## 四、开启 Pages（注意：Source 要选 Actions，不是分支）

1. 仓库 → **Settings** → **Pages**
2. **Source** 选 **`GitHub Actions`**（不是 "Deploy from a branch"）
3. 不用选分支、不用选目录 —— 工作流会把 `site/` 作为产物上传

> 第一次进来时 Branch 下拉显示 `None` 是正常的，**因为这里根本不选分支**。
> 这和 rizhilu 的做法一致。

---

## 五、第一次运行

1. 仓库 → **Actions** 标签
2. 左侧选「每日新闻 · 抓取与发布」
3. 右侧 **Run workflow** → 分支选 `main` → 运行

跑完大约 3–6 分钟。成功的话：

- 仓库里多出 `out/2026-XX-XX.md` 等文件（机器人自动提交）
- Pages 部署成功，打开 `https://dmk12318.github.io/Daily-News-Enhanced-Edition/` 能看到今天的日报

**想先试水不花 API 额度**：Run workflow 时勾上 `skip_editorial`，只抓新闻不写专栏。

## 六、日常工作流

```
云端（每天 08:00，全自动）
  抓取 → 选稿 → 判栏目 → 写三篇专栏 → 生成日报 → 渲染站点 → 发布
                              ↓
本地（你开机时，可选）
  校对云端专栏 → 覆盖 → 提交
```

### 本地校对（取代原来的全流程定时任务）

云端已经产出专栏，本地要做的只是**读一遍、改一遍**：

```powershell
cd D:\File\Codex\每日新闻
git pull                                  # 先把云端产物拉下来
notepad out\中国专栏.md                   # 直接改
notepad out\国际专栏.md
notepad out\中国境外专栏.md

python scripts/digest.py `
  --editorial 中国=out/中国专栏.md `
  --editorial 国际=out/国际专栏.md `
  --editorial 中国境外=out/中国境外专栏.md `
  --feed-time "<当天日期>T08:00"
python scripts/render_html.py --all
git add -A; git commit -m "主编校对 <日期>"; git push
```

推送后 Pages 自动重新发布。**校对版直接覆盖云端版**，不留两份。

> 如果你希望保留云端原稿做对照，把改动写成 `out/中国专栏.codex.md`，
> 让本地版和云端版并存——rizhilu 就是这么做的。要哪种告诉我。

## 七、云端和本地抓到的内容一样吗？——**不一样，这是必须知道的**

两者跑在不同的网络里，结果必然有差异：

| | 本地（你的机器） | 云端（GitHub Actions，服务器在美国） |
| --- | --- | --- |
| 境外源（路透、纽时、CNN） | 部分被 401/403 挡，靠 Google News 兜底 | **通常更顺**，能直连 |
| 境内源（新华社、澎湃、财新） | 直连顺畅 | **可能变慢甚至被挡** |
| 中文站点可用性 | 好 | 待实测 |

**所以不能假设两边内容一致。** 首次跑完云端后，用这个命令对比覆盖面：

```powershell
python scripts/analyze_coverage.py      # 看覆盖了多少源、重大故事簇命中率
```

把云端的 `data/*_report.json` 拉下来和本地的比一比就知道差在哪。

**如果云端在中国站点上损失太多**，两个补救方向：

1. 云端只抓境外源，境内源仍由本地补（混合模式）
2. 或者在云端给境内源也走 Google News 兜底（我们的 `gnews_fallback.py` 已支持中文区）

## 八、排错

| 现象 | 原因 |
| --- | --- |
| Actions 里没有这次运行 | 定时任务在高峰期会延迟；另外仓库 60 天无提交会被自动暂停（我们每天提交，不会触发） |
| 专栏文件是空的 | `EDITORIAL_THINKING` 没关。DeepSeek 的思考模式默认开，会把 `max_tokens` 吃光 |
| 专栏步骤失败但新闻正常 | 这是**故意设计的**：专栏步骤 `continue-on-error`，接口欠费/限流时新闻照发 |
| 数据没提交回仓库 | 检查 Settings → Actions → General → Workflow permissions 是否给了 `Read and write` |
| Pages 报 404 | 确认 Pages 的 Source 选的是 **GitHub Actions**，并且 deploy 那个 job 成功了 |
| 页面打开是上一期的 | Pages 有缓存，等 1–2 分钟；或强刷（Ctrl+F5） |

---

## 九、改了模型或时间怎么调

- **换模型**：Settings → Variables → 改 `EDITORIAL_MODEL`
- **换接口商**：改 `EDITORIAL_BASE_URL`（要兼容 OpenAI 的 `/chat/completions`）
- **改运行时间**：编辑 `.github/workflows/daily.yml` 里的 `cron`。
  它是 **UTC**，北京 08:00 = UTC 00:00。
